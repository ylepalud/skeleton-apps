# skeleton-apps (code and CI)

Context, decisions and critical rules: see the parent workspace's CLAUDE.md. This file only holds the rules specific to this repository. Detailed decisions and setup plan: `../docs/plan-apps.md`.

## Scope
- Gradle monorepo in Kotlin DSL, conventions in `build-logic` (precompiled script plugins).
- A single deployable for now: `services/api` (Spring Boot + Spring Modulith). Web app: `services/api-app` (Angular, built by Gradle).
- Produces Docker images published to GHCR.
- Holds no infrastructure: manifests and OpenTofu live in `platform`.
- No reference to an employer and no code taken from a professional project.

## Commands
- `./gradlew check`: full verification, including the TestKit tests of the convention plugins (`build-logic`).
- `./gradlew :build-logic:functionalTest`: only the convention plugin tests.
- `./gradlew :build-logic:spotlessApply`: formats the Kotlin code of `build-logic` (ktlint).
- `./gradlew pitest`: mutation testing, outside `check`, 80% threshold on `domain` and `application` (run nightly in CI).
- The Gradle daemon runs on Temurin 25 (`gradle/gradle-daemon-jvm.properties`), downloaded by foojay if missing. Any change to a convention plugin comes with a test in `build-logic/src/functionalTest`.

## Web app (`services/api-app`)
- Angular 22 zoneless, Tailwind 4, ESLint `strict`, Vitest + Testing Library, Playwright. Built by Gradle (`frontend-convention`, pinned Node, `npm ci`): `lint` and `test` in `check`, `build` in `assemble`.
- HTTP client generated from `contracts/api` (hey-api, `@hey-api/client-angular`) into `src/app/api/generated`, not committed. It goes through `HttpClient`: the OIDC interceptor adds the token, only towards `/api/`.
- Sign-in with Authorization Code + PKCE (angular-auth-oidc-client), renewed with refresh tokens. Settings read at runtime from `/config.json` (`authority`, `clientId`): `public/config.json` in dev, generated by nginx in the image.
- Dev: `npm start` (`ng serve`, `/api` proxied to `localhost:8080`) with the API in `bootRun`. E2E: `./gradlew :services:api-app:npmRunE2e -PrunE2e=true`, `E2E_BASE_URL` to target another stack; any console error fails a test.
- Image: `./gradlew :services:api-app:dockerBuild` (`skeleton-apps/api-app:local`), nginx-unprivileged on 8080. Variables: `API_UPSTREAM`, `OIDC_AUTHORITY`, `OIDC_CLIENT_ID`, `OIDC_ORIGIN` (CSP).
- npm `overrides`: js-yaml and vite forced to fixed versions; remove them once Angular and hey-api ship the fixes.

## Architecture
- Spring Modulith is mandatory: one application module = one top-level package under `dev.ylp`. `ApplicationModules.verify()` must pass.
- Inside a module, hexagonal layout (`java-conventions` skill): `domain` (model, ports), `application` (one use case per class), `adapter/in/<tech>` and `adapter/out/<tech>`. Roles are declared with jMolecules' hexagonal and DDD annotations (`@SecondaryPort`, `@SecondaryAdapter` on `package-info.java`, `@AggregateRoot`) and checked by `jmolecules-archunit`, plus one ArchUnit rule: `domain` and `application` depend neither on Spring (except `@Transactional`) nor on adapters.
- Use cases are declared in the module's `@Configuration`, without a Spring stereotype. Each port has an abstract contract test in `src/test`, extended by each adapter in `src/integrationTest`.
- `shared` is an open Modulith module (identifiers, `BusinessException`, `TechnicalException`); `config` holds cross-cutting concerns (`Clock`, `UUIDGenerator`).
- The domain depends on no framework.
- One Postgres schema per module, no join across schemas. A module only reads another module's data through its Java API or its events.
- Liquibase migrations, one changelog per module, included by the master.

## API
- The contract `contracts/api/` is the source of truth: change the contract first. `openapi.yaml` is the entry point, `common.yaml` holds `Problem` and the shared responses, one file per module (`notes.yaml`) with its tag. The Gradle project `:contracts:api` (`openapi-server` convention) generates the interfaces and DTOs (`Dto` suffix) that the controllers implement: compilation breaks if the code drifts from the contract. The `/api/v1` prefix of `servers` is applied to `@RestController`s by `ApiPathConfiguration`.
- A second module will need one generation per tag (`FILTER` normalizer), so each module owns its DTOs.
- The web app's client (hey-api) and the future CLI are generated from the same contract.
- Every API change is mirrored in the Bruno collection (`bruno/`, `bruno-collection` convention): after changing the contract, run `./gradlew :bruno:updateCollection` and commit; `check` fails otherwise (`verifyCollection`). Only the request folders (`notes/`, one per tag) are generated; `opencollection.yml` (OAuth2 `client_credentials` auth, shared test) and `environments/` (`Stack`, `BootRun`) are written by hand. Give request bodies an `example` in the contract, or the generated request is sent empty.
- Spring Security as a resource server, JWTs from an OIDC provider, checked for issuer and the `api` audience. No anonymous route. Resources belong to the token's `sub`, read only by `CurrentOwner`; accessing someone else's returns 404.
- Errors as `ProblemDetail` (RFC 9457), with `errorCode` and `hint`. A business reason declares its `category()` (`NOT_FOUND`, `INVALID`, `CONFLICT`, `RULE_VIOLATION` by default) without knowing anything about HTTP; `ProblemDetailsExceptionHandler` maps it to a status. Messages in English (fixed locale).
- Request bodies limited to 64 KiB (`RequestSizeLimitFilter`, 413).
- Actuator on management port 8081, only `health` (liveness, readiness), `info` and `prometheus`. Never routed by the Ingress.
- Strict CORS, input validation, request size limits.

## Build and images
- API: Jib, distroless `nonroot` base (otherwise a non-root Temurin JRE) pinned by digest. Web app: minimal `nginx-unprivileged` Dockerfile, the only exception to Jib.
- Local image names derive from the root project name: `skeleton-apps/api:local`, `skeleton-apps/api-app:local`.
- Versions: libraries in `gradle/libs.versions.toml`, build tools in `gradle.properties`, libraries managed by the Boot BOM without a version.
- Public repository `github.com/ylepalud/skeleton-apps`, marked as a *template*: the starting point of future projects ("Use this template").
- GitHub Actions CI (`.github/workflows`), actions pinned by commit SHA, minimal permissions:
  - `ci.yml` (pull requests to `develop`/`main`, push to `main`): jobs `check`, `e2e` (full stack, Playwright, Bruno smoke run) and `trivy-fs` (dependencies including dev ones, secrets, configuration; SARIF in the Security tab). These three checks are required by the rulesets.
  - `publish.yml` (push to `develop`): `ci.yml`, then for each image whose code changed, push `ghcr.io/ylepalud/skeleton-apps/<api|api-app>:<sha>`, Trivy scan, attested SPDX SBOM and keyless cosign signature (`.github/actions/secure-image`). Signed only if the scan passes. `workflow_dispatch` republishes everything.
  - `nightly.yml`: PIT at 80%. `release.yml`: release-please on `main`, then the `vX.Y.Z` tag added to the images already published (no rebuild).
- CI authenticates to GHCR with the built-in GitHub token, no long-lived secret.
- Immutable image tags (commit SHA). No `latest` tag for deployment.

## Branches and versions
- `develop` is the default branch and the only one deployed. Pull requests target `develop`.
- `main` receives releases: a `develop` to `main` pull request merged with a *merge commit* (pull requests to `develop` are *squashed*), then release-please opens the release pull request that sets the `vX.Y.Z` tag.
- release-please's release pull request is created with the `GITHUB_TOKEN`: it triggers no workflow, hence no check, and the `main` ruleset blocks it. It only touches `CHANGELOG.md` and the manifest: merge it with the admin bypass, `gh pr merge <n> --merge --admin`. Possible improvement: a GitHub App token for release-please, so its pull requests run CI (issue #12).
- A pull request that only touches `.github/` or configuration publishes no image (path filter): `gh workflow run publish.yml --ref develop -f all=true` republishes everything.

## Quality
- Tests mandatory before merging. Domain tested without Spring. Spring tests and JPA slices on Testcontainers Postgres, never H2.
- `check` includes JaCoCo (80%), Spotless, ErrorProne and NullAway, Modulith and jMolecules, the web app's lint and tests, the Bruno check.
- Dependencies kept up to date by Renovate (`renovate.json`; the Mend Renovate GitHub App must be installed on the repository, issue #11): seven days minimum age, automatic merge of patch, minor and digest updates when CI passes, except Spring, Angular, PostgreSQL and majors. Versions in `gradle.properties` carry a `# renovate:` comment.
- No secret in code, tests or committed configuration files.

## Local development
- A single `compose.yaml` at the root (compose project `skeleton-apps`). By default: postgres and mock-oauth2-server (8090). Profile `app`: the API (Jib image `skeleton-apps/api:local`, probes on 8091) and the web app (nginx image `skeleton-apps/api-app:local`, http://localhost:8088, `/api` proxied to the API).
- `./gradlew startLocalStack` builds both images, starts everything and waits for readiness; running it again after a change only recreates the containers whose image changed. `stopLocalStack` keeps the database, `resetDatabase` deletes it.
- `./gradlew :services:api:bootRun` starts postgres and the mock from the same compose file (without the `app` profile). Do not run the API in `bootRun` and in a container at the same time.
- In the container, the API checks the issuer `http://localhost:8090/default` (that of the browser's tokens) but reads the keys at `http://mock-oauth2-server:8080/default/jwks`: there, `localhost` does not mean the host.
- Bruno against the stack: `cd bruno && npm run smoke`. E2E against the stack: `E2E_BASE_URL=http://localhost:8088 ./gradlew :services:api-app:npmRunE2e -PrunE2e=true`.
- Local token: `curl -X POST localhost:8090/default/token -d grant_type=client_credentials -d client_id=<user> -d client_secret=x` (the `sub` is the `client_id`).
- Tasks that call docker resolve it from the caller's `PATH` (`dev.ylp.buildlogic.dockerExecutable`): a Gradle daemon may have a minimal `PATH`.
